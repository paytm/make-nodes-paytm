Design Decision — Pagination Cursor for Search Modules DECIDE BEFORE REVIEW P1

Four search modules send a pageNum/pageNumber cursor to the Paytm API. The JSONC files reference this as parameters.pageNum. A decision is needed on how users advance through pages.

Expose pageNum as a Number parameter in Make UI. Users set it manually or use a Make iterator to advance. Simple to implement but not how Make's native pagination works.

✓ Simplest. No IML changes. Just define the parameter.

Use Make's cursor bundle. The module returns the next page cursor and Make automatically calls the module again until exhausted. Requires IML changes to set response.cursor and read it back.

⚠ Requires IML work and E2E verification. Best UX but more complex.

Recommendation: Ship Option A (manual pageNum) for the first review submission. This unblocks review without IML changes. Add a help text note: "Increase page number to get the next set of results." Upgrade to Option B (cursor) in a follow-up iteration.
